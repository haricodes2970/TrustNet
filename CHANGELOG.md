# Changelog

Derived from `git log`. Format loosely follows [Keep a Changelog](https://keepachangelog.com/); this repo has no version tags yet, so entries are grouped by commit rather than release version. TODO: adopt semantic version tags if/when the API stabilizes (see [ROADMAP.md](ROADMAP.md)).

## Unreleased

- `feat(applications)`: add Applications module — model (`Application.js`, flat resume storage metadata, no persisted URL, `notes` as a single string not an array, partial unique index on `{job,applicant}` excluding `withdrawn`), CRUD+lifecycle service/controller/routes (`/api/v1/applications`, no public tier, dedicated `/resume`/`/cover-letter`/`/status`/`/withdraw` endpoints instead of a generic update), Joi validators. Reuses `jobService.resolveStartupAccess`/`storageService` directly — no `Document`/`documentService`. New pure `assertValidStatusTransition` (unit-tested state machine) and `redactForCandidate` (first per-viewer field redaction in this codebase) in `applicationService.js`. Contributor gets zero access (stricter than Job's read-only contributor tier). Fixed a test-infra concurrency race (shared local-storage cleanup between Documents' and Applications' integration tests under `npm run test:all`) via `fs.rm`'s `maxRetries`/`retryDelay` — not a production bug. Added `test/application.test.js` (12 tests) + `test/integration/applicationAuthorization.test.js` (28 tests) — 190/190 combined passing. (uncommitted)
- `feat(hiring)`: add Hiring module — Job model (`Job.js`, Startup-only relationship, no Workspace/Project/Documents dependency), CRUD + publish/unpublish service/controller/routes (`/api/v1/jobs`, first public-unauthenticated read surface in this codebase), Joi validators (loose for drafts, strict business rules `validateSalaryRange`/`assertPublishReady` at publish time). `jobService.js` implements its own `resolveStartupAccess()`/`getAccessibleStartupIds()` — a deliberate, explicitly-instructed duplication of `workspaceService`'s role logic, not a shared extraction (collaboration permission layer left untouched per instruction). Owner/admin full management; contributor read-only; public sees published-only, unpublished jobs return 404 not 403. List endpoint "downgrades to public subset" on an unauthorized filter rather than rejecting. Added `createStartupTeamFixture()` to `collaborationFixtures.js` (proves Workspace/Project independence by construction; existing fixture's behavior unchanged, re-verified). `test/job.test.js` (11 tests) + `test/integration/jobAuthorization.test.js` (27 tests) — 150/150 combined passing. (uncommitted)
- `feat(documents)`: add Documents module — model (`Document.js`, no persisted `url`, `storageProvider`/`storageKey`/`checksum` only), `storageService.js` abstraction (`upload`/`downloadUrl`/`remove`, local-disk default provider, no external provider chosen), CRUD service/controller/routes (`/api/v1/documents`, one-shot multipart upload matching existing `profile`/`verification` route convention), Joi metadata validators (file validation via multer `fileFilter`/`limits`, not Joi), dedicated `canMutateDocument()` helper (explicitly separate from `canMutateTask()`). Contributors may upload/view any document, update/archive only their own uploads; owner/admin manage any. Added `test/document.test.js` (11 unit tests) and `test/integration/documentAuthorization.test.js` (20 integration tests, reusing the existing collaboration fixture) — 112/112 combined tests passing. `ARCHITECTURE.md` module-map gap (missing Workspace/Project/Task/Milestone rows from prior phases) fixed while touching that table. Versioning/previews/OCR/comments/folders/collaborative-editing/sharing explicitly out of scope. (uncommitted)
- `chore(testing)`: add `mongodb-memory-server`-backed integration-test infrastructure (`test/integration/` — `helpers/db.js` setup/teardown/cleanup, `helpers/testUser.js` authenticated-test-user creation, one infra-smoke-test file, `README.md`). New npm scripts `test:integration`/`test:all`; `test` (unit-only) unchanged, re-verified 37/37 passing. No Jest introduced — repo has none, built on the existing `node --test` runner. No collaboration-permission integration tests written yet (explicitly out of scope this phase). (uncommitted)
- `feat(milestones)`: add Milestones module (Sprint 1 Phase 4) — model (`Milestone.js`, structural planning entity, owner/admin-only permissions via `workspaceService.resolveWorkspaceAccess()`), CRUD service/controller/routes (`/api/v1/milestones`), Joi validators. Task-module change: `Task.milestone` (nullable ref, **update-only**, not settable at create) with a project-integrity check (`taskService.assertMilestoneBelongsToProject`); Task's existing permission logic untouched, full existing test suite re-confirmed passing. `GET /api/v1/tasks?milestone=<id>` works with no Task-listing code change (generic filter passthrough already supported it). Added `test/milestone.test.js`. Documents intentionally out of scope. (uncommitted)
- `feat(tasks)`: add Tasks module (Sprint 1 Phase 3) — model (`Task.js`, no denormalized workspace ref by design, resolved through Project), CRUD service/controller/routes (`/api/v1/tasks`), Joi validators. First module with non-owner/admin write access: new pure `canMutateTask()` helper in `serviceUtils.js` (unit-tested) composes with `workspaceService.resolveWorkspaceAccess()` — contributors may mutate only their own created/assigned tasks; `assignedTo` validated as an active workspace member, contributors may only self-assign. Added `test/task.test.js` (validator + `canMutateTask` unit tests, no DB). Milestones/Documents intentionally out of scope. (uncommitted)
- `feat(projects)`: add Projects module (Sprint 1 Phase 2) — model (`Project.js`, `owner`=creator audit-only, `updatedBy` audit trail, `status` business-lifecycle-only), CRUD service/controller/routes (`/api/v1/projects`), Joi validators. All authorization exclusively via `workspaceService.resolveWorkspaceAccess()` — `owner`/`status` never used for permissions. Fixed a permission-bypass caught during implementation (`?workspaceId=` filter now re-verified, not trusted). Added `test/project.test.js` (Joi validator unit tests, no DB). Tasks/Milestones/Documents intentionally out of scope. (uncommitted)
- `feat(workspace)`: add Workspace module Phase 1 — model (`Workspace.js`, one-per-startup via unique index on `startup`), CRUD service/controller/routes (`/api/v1/workspaces`), Joi validators, permission resolution (`resolveWorkspaceAccess`, founder=owner / active Team admin=admin / active Team member=contributor, no separate pure-function split per explicit scope decision). Queries `Team`/`Startup` models directly, no `teamService` coupling. Added `test/workspace.test.js` (Joi validator unit tests, no DB). Projects/Tasks/Milestones/Documents intentionally out of scope. (uncommitted)
- `refactor(teams)`: extract shared `assertOwner` ownership helper in `serviceUtils.js`, reused by `teamService.js` and `startupController.js`; `teamService.inviteMember` now uses `userService.getUserByEmail` instead of querying `User` directly; notifications added for team-invite-accepted, member-removed/left, and role-changed events; swallowed notify/email errors in `inviteMember` now logged; added `test/serviceUtils.test.js` and wired `npm test` to `node --test` (previously a no-op). ## How to update this file

Add an entry under `Unreleased` for every merged PR that changes API behavior, adds a module, or fixes a security issue. Reference the commit hash. When a release is cut, rename `Unreleased` to a version + date and start a new `Unreleased` section. See [CONTRIBUTING.md](CONTRIBUTING.md).
