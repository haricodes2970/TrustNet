# Changelog

## Unreleased

- `chore(merge)`: compare and merge an independently-developed TrustNet backend ("Developer 1", `trustnet 2.zip`) against this repo ("Developer 2"). Developer 1 had zero automated tests and a structurally different domain model (22 additional models — social graph, admin/audit, realtime, background jobs, its own AI gateway — none on this roadmap; every one of 12 shared model names differed in schema). Explicit scope decision: keep Developer 2's architecture/models wholesale, adopt only two self-contained, non-duplicative pieces that each closed a standing `BACKLOG.md` Phase 1 gap: `src/middlewares/sanitizer.js` (NoSQL-injection/XSS-at-the-edge sanitization, fixed for Express 5's getter-only `req.query`) and `src/middlewares/rateLimiter.js` + `src/config/rateLimits.js` (`express-rate-limit`-based; dropped Developer 1's `auditLogService` coupling, fixed IPv6 key generation). Wired into `app.js` (global) and `auth.routes.js`/`search.routes.js`/`ai.routes.js` (per-route). New dependency: `express-rate-limit@^8.6.0`. Added `test/sanitizer.test.js` (8 tests) + `test/rateLimiter.test.js` (5 tests) — 452/452 combined passing, no regressions. (uncommitted)
- `feat(ai)`: add AI module — final roadmap item. Thin, fully stateless orchestration layer, no model, no persistence (no conversations/embeddings/vector store/RAG/agent framework/workflow engine). `aiService.js` performs zero authorization of its own — every one of eight capabilities dispatches to an existing `analyticsService`/`reportService`/`taskService`/`serviceListingService` function and inherits that call's authorization unmodified, including `report-explanation` correctly denying contributor (Reports' stricter gate) while every other capability allows contributor (Analytics' any-role gate). One narrow normalization of `taskService`'s pre-`ApiError` plain `Error` into `ApiError(403)`, not a new authorization decision. Exactly one provider abstraction (`aiProviderService.generateCompletion()`) backed by a deterministic no-network default — real LLM provider wiring explicitly deferred to `BACKLOG.md` (named options), same treatment PDF received in Reports. Deterministic three-part prompt construction (system prompt → context → question), pure and unit-tested. Provider failures → 502 (first in this codebase); rate-limit exhaustion → 429 (first in this codebase), lightweight in-memory per-user limiter (10/min). `POST /api/v1/ai/insights`, capability in body (supports Joi `.when()` conditionals) — first new validator file since Marketplace. Added `test/ai.test.js` (14 tests) + `test/integration/aiAuthorization.test.js` (16 tests, including a monkey-patched provider-failure test and per-user rate-limit isolation) — 439/439 combined passing. (uncommitted)
- `feat(reports)`: add Reports module — presentation/export layer over Analytics, no model of its own, no domain-model queries in `reportService.js`. `GET /api/v1/reports/:reportType` (`startup|projects|tasks|hiring|funding|marketplace`, `?startupId=` required, `?format=json|csv` default json) dispatches through a lookup table to the corresponding `analyticsService` function. Reuses `analyticsService.resolveStartupAccess`/`assertAnyRole` directly — no seventh Startup authorization helper — narrowed to owner/admin only (contributor gets 403, a deliberate divergence from Analytics' any-role gate). JSON (envelope passthrough) and hand-rolled CSV (pure `flattenToRows`/`escapeCsvField`/`toCsv`, RFC 4180 escaping, no new dependency) export formats; PDF explicitly deferred to `BACKLOG.md` (library options recorded, not implemented). `format=csv` is the first response in this codebase to bypass the `{success,data}` envelope. Added `test/report.test.js` (9 tests) + `test/integration/reportAuthorization.test.js` (14 tests) — 409/409 combined passing. (uncommitted)
- `feat(analytics)`: add Analytics module — read-only, no model of its own, first fully read-only module (every route is `GET`, no writes anywhere). `analyticsService.js` computes counts/rates on demand directly from `Startup`/`Workspace`/`Project`/`Task`/`Milestone`/`Job`/`Application`/`InvestmentInterest`/`FundingRound`/`FundingContribution`/`ServiceListing`/`EngagementRequest`/`Team`. Own `resolveStartupAccess()` — a sixth deliberate duplication of the role logic in `workspaceService`/`jobService`/`investmentInterestService`/`fundingRoundService`/`engagementRequestService`, tracked in `BACKLOG.md`. Six endpoints (`/api/v1/analytics/overview|projects|tasks|hiring|funding|marketplace`, `?startupId=` query param, any-role authorization gate). No admin/platform-wide surface (out of scope, explicit decision). No new persistent model — `AnalyticsSnapshot`-style caching deferred to `BACKLOG.md`. New pure `defaultCounts()` helper (unit-tested). Added `test/analytics.test.js` (4 tests) + `test/integration/analyticsAuthorization.test.js` (13 tests, including exact-count correctness against a seeded cross-domain fixture and an overview-consistency check) — 386/386 combined passing. (uncommitted)
- `feat(marketplace)`: add Marketplace module — `ProviderProfile` (`User → ProviderProfile`, public directory, flat ownership), `ServiceListing` (`ProviderProfile → ServiceListing`, draft/published/archived lifecycle mirroring Job), `EngagementRequest` (`Startup → EngagementRequest ← ServiceListing`, requested/accepted/declined/in_progress/completed/cancelled lifecycle) models, CRUD+lifecycle service/controller/routes (`/api/v1/provider-profiles`, `/api/v1/service-listings`, `/api/v1/engagement-requests`), Joi validators. `engagementRequestService.js` implements its own `resolveStartupAccess()` — a fifth deliberate duplication of the role logic in `workspaceService`/`jobService`/`investmentInterestService`/`fundingRoundService`, tracked in `BACKLOG.md`. First resource requiring two independent authority mechanisms simultaneously (Startup-role + flat provider ownership). Providers are individual Users, not Startups, by design. `ServiceListing` reuses Job's/FundingRound's 404-existence-concealment convention. Partial unique index on `{serviceListing,startup}` excludes three terminal statuses, permitting re-engagement after any terminal outcome including completion. New pure `assertValidEngagementTransition` (unit-tested, most complex transition table so far — two actors, two non-terminal exit points). Typed `ApiError` (400/403/404/409) used throughout. Added `test/providerProfile.test.js` (5) + `test/serviceListing.test.js` (12) + `test/engagementRequest.test.js` (13) + `test/integration/marketplaceAuthorization.test.js` (60+ tests, including explicit cross-provider/cross-startup isolation and re-engagement-after-terminal-state coverage) — 369/369 combined passing. (uncommitted)

New pure `assertValidRoundTransition`/`assertValidContributionTransition` (unit-tested state machines, kept separate per convention). Typed `ApiError` (400/403/404/409) used throughout.
